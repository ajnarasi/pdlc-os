# PDLC-OS — Investor Video Script

> Target runtime: **2:30–3:00**. Recorded against the live deploy at https://pdlc-os.vercel.app/ with the Lovable proof at https://grab-nexus-flow.lovable.app/. Read at ~150 WPM.

Format per beat: `[SCREEN]` what's visible · `[SAY]` the narration · `[POINTS]` underlying claims for ad-lib safety.

## Beat 1 · Hook (0:00–0:18)

- **[SCREEN]** Static slide showing six disconnected lifecycle workflows (Discovery, Prioritization, Design, Delivery, Launch, Support) as separate boxes with broken arrows between them. Quick caption: *"Where institutional memory goes to die."*
- **[SAY]** *"Every product team runs the same six-stage lifecycle. Discovery to Support. They use a different tool for each stage, and almost none of the evidence survives the handoff. Three quarters in, you're rebuilding context that already exists somewhere in the org. The cost is real — and it compounds in the wrong direction."*
- **[POINTS]**
  - Lifecycle stages are universal; tooling is fragmented.
  - The artifact disposable problem: PRDs get re-written, not extended.
  - Cost of rebuilding context is the silent tax on every product org.
  - This is not a new productivity tool category — it's a memory category.

## Beat 2 · The category claim (0:18–0:35)

- **[SCREEN]** Cut to https://pdlc-os.vercel.app/ — the dashboard with all 9 stage cards visible. Pause on the header: *"PDLC·OS · one brain across 6 canonical + 3 extension stages."*
- **[SAY]** *"PDLC-OS makes the lifecycle one continuous, evidence-locked agent run. Every stage feeds the next. Every artifact is signed. The whole brain compounds with each merchant scenario you put through it. It is not a wiki, not a chatbot — it is a memory system for product orgs."*
- **[POINTS]**
  - One-sentence positioning: a compounding memory system for the product lifecycle.
  - 9 stages, not 6 — three extension stages (Marketing, Sales Enablement, E2E Test Plan) take the lifecycle past Support.
  - Per-merchant brain is the unit of value, not per-feature or per-doc.
  - Signed audit ribbon is the FinTech-grade differentiator, not a nice-to-have.

## Beat 3 · Live demo: pain → 9-stage brain (0:35–1:25)

- **[SCREEN]** On the deployed app, click the scenario library. Show the 25-archetype grid scrolling briefly. Pick A1 — *Mid-Market Fashion D2C + Omnichannel*. Discovery → Prioritization → Design → Delivery → Launch → Support → Marketing → Sales Enablement → E2E Test Plan.
- **[SAY]** *"One pain point. Real LLM. Watch the cascade. Discovery picks the archetype from the locked catalog — A1, mid-market fashion D2C. Prioritization runs the driver tree, hits a GO. Design produces the ISO 20022 envelope and the Commerce Hub field map. Delivery emits the tickets. Launch sets the success metrics. Support closes the loop. Marketing, Sales, and a full QA test plan write themselves."*
- **[POINTS]**
  - Live LLM, not pre-baked — every artifact is generated against the catalog and the prior stages.
  - The audit ribbon (bottom of screen) populates one card at a time — you can SEE the chain forming.
  - Each stage takes 5–10 seconds; the whole cascade is under two minutes.
  - The demo is reproducible — anyone with an API key can run the same flow on the deployed URL.

  - The substrate compounds: every new merchant scenario adds JTBDs that future runs can pattern-match against.

## Demo run sheet — exactly what to click

For the live recording, follow this sequence. Have the backup paths in mind in case any single beat misbehaves.

1. **Open** https://pdlc-os.vercel.app/?merchant=A1 in a fresh browser window. Disable any extensions that overlay the page.
2. **Confirm** the dashboard renders 9 stage cards with the *— EXTENSION STAGES —* separator visible between Support and Marketing.
3. **Open** the scenario library, scroll to A1 (Slice A), close.
4. **Type** in the pain box: `Brazilian buyers abandon at checkout — we don't accept Pix.` (Or pick `Brazilian buyers abandon…` from the seeded buttons.)
5. **Switch** Run mode to *Live · Anthropic*. Confirm the API key is set (gear icon).
6. **Click** *Run all six stages* (label updates as the run progresses through 9 stages).
7. **Wait** ~60–90 seconds. Watch the audit ribbon populate; do not interrupt.
8. **Once** all 9 cards are green, click into Discovery — show the JTBD block expanded.
9. **Click** into Design — scroll past the field map → ISO envelope → unmappable fields → napkin sketch → **prototype prompt**. Copy the prompt.
10. **Switch tabs** to https://grab-nexus-flow.lovable.app/ as the worked example. (Optional live recreation: paste the prompt into Lovable; on stage time this is risky, prefer pre-recording.)
11. **Switch back** to PDLC-OS. Click *Panel review* on Design. Wait ~10 seconds for 7 reviewers to populate.
12. **Click** *Export PRD* in the header. The modal opens with a 10-section PRD synthesized across all 9 stages.
13. **Close** the modal. Click into the audit ribbon at the bottom. Click an entry to show the signed citation chain back to Discovery.

## Backup paths if anything fails on stage

- If Live · Anthropic times out on a stage — switch to *Cached demo* and replay; the screen recording still tells the same story.
- If Lovable is slow — drop the live paste; the existing https://grab-nexus-flow.lovable.app/ tab is enough.
- If the deploy is flaky — fall back to a 90-second pre-recorded Loom of the same flow. Have it ready in the same Loom workspace as the live recording.
